# PROOFCHAIN
## UI/UX GUIDELINES

Versão: 2.0

---

# Objetivo

Definir as regras de experiência e interface do usuário.

A interface do ProofChain deve transmitir:

- confiança;
- segurança;
- tecnologia;
- simplicidade;
- profissionalismo.

O resultado não deve parecer uma landing page genérica ou template.

---

# Princípios de UX

A experiência deve ser:

- simples;
- intuitiva;
- previsível;
- elegante;
- responsiva.

O usuário deve compreender rapidamente:

- o que é o ProofChain;
- qual problema resolve;
- como funciona;
- como acessar a plataforma.

---

# Hierarquia Visual

Toda página deve possuir:

## Elemento principal

O conteúdo mais importante da tela.

## Elementos secundários

Informações complementares.

## Ações

Botões e chamadas para conversão.

Evitar competição visual entre elementos.

---

# Header / Navbar

A Navbar deve:

- permanecer fixa durante a navegação;
- possuir fundo transparente inicialmente;
- alterar visual após scroll;
- utilizar efeito blur discreto;
- manter boa legibilidade.

Estrutura:

```
Logo

Sobre

Recursos

Como Funciona

Planos

Contato

[ Entrar ]
```

---

# Navegação

Os links do menu devem apontar para as seções correspondentes.

Utilizar:

- Smooth Scroll;
- Scroll Spy;
- destaque do item ativo.

Exemplo:

Sobre

↓

<section-about>

Recursos

↓

<section-features>

Como Funciona

↓

<section-process>

Planos

↓

<section-pricing>

---

# Botão Entrar

O botão "Entrar" é a principal ação da Navbar.

Comportamento:

Clique:

```
/login
```

O botão deve possuir maior destaque visual.

---

# Hero Section

A Hero deve possuir equilíbrio entre texto e imagem.

Não utilizar títulos gigantes.

O título deve:

- possuir boa leitura;
- ocupar espaço proporcional;
- não competir com a ilustração.

Estrutura:

```
Badge

Título

Descrição

CTA

Imagem Certificado
```

---

# CTAs da Hero

A Hero deverá possuir:

## Primário

Conheça os Planos

## Secundário

Validar Certificado

Os botões devem possuir hierarquia visual diferente.

---

# Cards

Todos os cards devem evitar aparência simples ou quadrada.

Aplicar:

- bordas suaves;
- profundidade;
- sombra discreta;
- hover elegante.

---

# Hover dos Cards

Aplicar nas seções:

- Por que contratar;
- Recursos;
- Casos de Uso;
- Como Funciona.

Comportamento:

Mouse sobre:

- leve zoom;
- elevação;
- destaque da borda;
- transição suave.

Exemplo:

```
scale(1.02)

translateY(-4px)
```

---

# Como Funciona

A linha de conexão entre etapas deve ser claramente visível.

Regras:

- não utilizar linha com contraste insuficiente;
- espessura mínima perceptível;
- utilizar azul da identidade;
- aplicar glow discreto.

O fluxo deve ser compreendido rapidamente.

---

# Botões

Todos os botões devem possuir:

- estado normal;
- hover;
- active;
- focus;
- disabled.

---

# Hover dos Botões

O hover deve possuir contraste perceptível.

Aplicar:

- mudança de luminosidade;
- glow azul;
- elevação;
- transição suave.

Evitar alterações quase imperceptíveis.

---

# Animações

As animações devem:

- melhorar percepção;
- orientar usuário;
- transmitir qualidade.

Evitar:

- movimentos exagerados;
- efeitos chamativos;
- excesso de elementos animados.

---

# Responsividade

Toda experiência deve funcionar em:

- Desktop;
- Tablet;
- Mobile.

A navegação nunca deve quebrar.

---

# Resultado Esperado

A interface deve parecer um produto SaaS profissional e não uma página acadêmica.
