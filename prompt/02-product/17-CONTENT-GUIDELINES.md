# PROOFCHAIN
## Content Guidelines

Versão: 2.0

---

# Objetivo

Definir padrões para criação dos textos e mensagens utilizados na interface.

O conteúdo deve comunicar valor, confiança e tecnologia sem excesso de complexidade técnica.

---

# Princípios de Comunicação

A comunicação deve ser:

- clara;
- objetiva;
- profissional;
- confiável;
- orientada ao benefício.

Evitar textos genéricos.

---

# Posicionamento

O ProofChain deve ser apresentado como:

Uma plataforma SaaS para emissão, gerenciamento e validação de certificados digitais com segurança e autenticidade.

---

# Linguagem

Utilizar linguagem:

- empresarial;
- moderna;
- simples.

Evitar:

- excesso de termos técnicos;
- frases muito longas;
- explicações complexas.

---

# Hero

A Hero deve responder rapidamente:

## O que é?

Uma plataforma de certificados digitais.

## Qual problema resolve?

Fraudes, dificuldade de validação e falta de confiança em documentos digitais.

## Qual benefício entrega?

Autenticidade, segurança e validação simples.

---

# Headline

A headline deve ser:

- curta;
- forte;
- memorável.

Evitar títulos excessivamente longos.

Exemplo de direção:

"Certificados digitais seguros, verificáveis e confiáveis."

---

# Subheadline

Complementar a mensagem principal.

Deve explicar:

- como funciona;
- para quem é;
- principal benefício.

---

# Botões

Os textos dos botões devem indicar ação clara.

Preferir:

```
Entrar

Validar Certificado

Conhecer Planos

Começar Agora
```

Evitar:

```
Clique Aqui

Enviar

Continuar
```

---

# Recursos

Cada recurso deve responder:

- qual funcionalidade existe;
- qual benefício entrega.

Exemplo:

Ruim:

"Blockchain"

Bom:

"Registro seguro utilizando tecnologia Blockchain para garantir autenticidade."

---

# Como Funciona

O fluxo deve possuir textos simples.

Exemplo:

```
Emitir

A instituição cria o certificado digital.

Registrar

A autenticidade é protegida.

Compartilhar

O certificado pode ser enviado.

Validar

Qualquer pessoa pode verificar.
```

---

# Casos de Uso

Os textos devem mostrar aplicação prática.

Exemplo:

Instituições de Ensino:

"Emita certificados digitais para alunos e cursos."

Empresas:

"Comprove treinamentos e qualificações."

---

# Planos

Os planos devem destacar:

- benefícios;
- limites;
- diferenciais.

Evitar excesso de informações.

---

# Dashboard

Os textos devem parecer reais.

Exemplo:

Evitar:

```
Lorem Ipsum
```

Utilizar:

```
Certificados emitidos

Cursos ativos

Validações realizadas
```

---

# Mensagens do Sistema

Mensagens devem ser amigáveis.

Exemplo:

Erro:

```
Certificado não encontrado.
Verifique o código informado.
```

Sucesso:

```
Certificado validado com sucesso.
```

---

# Validação Pública

A comunicação deve reforçar confiança.

Exemplo:

"Consulte a autenticidade deste certificado utilizando o código informado."

---

# Tom da Marca

O ProofChain deve comunicar:

- confiança;
- inovação;
- segurança;
- simplicidade.

---

# Resultado Esperado

O usuário deve entender a proposta da plataforma rapidamente, mesmo sem conhecimento técnico sobre Blockchain.
