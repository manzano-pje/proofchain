📘 PROOFCHAIN — PADRÃO OFICIAL DE DOCUMENTAÇÃO DE CÓDIGO
📌 Versão: 1.0 (Arquitetura em Evolução)

Este documento define o padrão obrigatório de documentação das classes do sistema ProofChain, com foco em:

clareza arquitetural
rastreabilidade de fluxo
baixa redundância
escalabilidade para sistemas distribuídos (JWT / Security / Multi-tenant)
🧭 1. ESTRUTURA PADRÃO DE CLASSE

Toda classe deve seguir o modelo abaixo:

 /**
  * ClassName
  *
  * Função no sistema:
  *
  * Estrutura atual:
  *
  * Fluxo:
  *
  * Integração no sistema:
  */
🧩 2. DEFINIÇÃO DOS CAMPOS
✔ 2.1 Função no sistema (OBRIGATÓRIO)
📌 Descrição

Define o papel da classe dentro do sistema.

📌 Deve conter:
responsabilidade técnica
papel arquitetural
contexto funcional
objetivo da classe
📌 Exemplo:
Responsável por autenticar usuários e gerar JWT após validação de credenciais.
Atua como orquestrador do fluxo de login no sistema.
⚠️ 2.2 Estrutura atual (CONDICIONAL)
📌 Quando usar:
classes complexas
múltiplos atributos relevantes
DTOs com composição
services com múltiplas dependências
📌 Quando não usar:
DTOs simples
classes triviais
utilitários simples
⚠️ 2.3 Fluxo (CONDICIONAL)
📌 Descreve:

Sequência de execução ou comportamento runtime.

📌 Usar quando:
existir cadeia de chamadas
houver orquestração (Service / Filter / Controller)
lógica de autenticação ou processamento
📌 Exemplo:
Request → Controller → Service → JwtService → Response
⚠️ 2.4 Integração no sistema (CONDICIONAL)
📌 Descreve:

Onde a classe se encaixa na arquitetura.

📌 Deve responder:
quem chama esta classe
quem depende dela
em qual camada ela atua
📌 Exemplo:
Utilizado pelo AuthController no fluxo de autenticação.
Integra a camada de segurança com o núcleo de autenticação JWT.
🧱 3. SEPARAÇÃO DE SEÇÕES INTERNAS

Para organização técnica dentro da classe:

 /*
  * =========================================================
  * CONFIGURAÇÕES
  * =========================================================
  */
📌 Usar para:
dependências
constantes
configurações internas
blocos lógicos
📄 4. DOCUMENTAÇÃO DE MÉTODOS (JAVADOC)

Todo método público deve seguir padrão JavaDoc:

 /**
  * Descreve o comportamento do método.
  *
  * @param param descrição do parâmetro
  * @return descrição do retorno
  * @throws Exception descrição da exceção
  */
🧠 5. REGRAS ARQUITETURAIS DO PROOFCHAIN
✔ Obrigatório em todas as classes:
Função no sistema
✔ Condicional (uso inteligente):
Estrutura atual
Fluxo
Integração no sistema
❌ Proibido:
duplicar Responsabilidade + Função
documentação redundante
explicação óbvia de código
inflar DTOs simples com campos desnecessários
